# Movie Recommender (Pure SQL — Oracle)

A collaborative-filtering-style movie recommendation system implemented
**entirely in SQL** — no ML libraries, no application layer. Finds users
with similar taste and recommends what they liked that you haven't seen yet.

## Pitch

> "I implemented collaborative filtering as a single SQL query using
> self-joins and a subquery — not a trained ML model."

## How it works

1. Find users who rated the same movies as you highly (self-join on `ratings`)
2. Find what those similar users also liked
3. Exclude movies you've already rated (`NOT IN` subquery, or `LEFT JOIN` variant)
4. Rank the results using window functions (`RANK()`)

## Schema

- **users** — id, name, email
- **genres** — id, genre_name
- **movies** — id, title, genre_id, release_year
- **ratings** — id, user_id, movie_id, rating (1–5), rated_on

## How to run (Oracle SQL — SQL Developer or SQL*Plus)

1. Open Oracle SQL Developer and connect to your existing Oracle XE
   user/schema (e.g. `SYSTEM` or a custom user you set up earlier).
2. Open and run each file in order using **Run Script (F5)**, not just
   "Run Statement" — these files contain multiple statements:
   - `sql/01_schema.sql` — creates the four tables
   - `sql/02_sample_data.sql` — inserts dummy data (sets the session
     date format, then commits)
   - `sql/03_basic_queries.sql` — run individual `SELECT`s to see
     aggregates
   - `sql/05_recommendations.sql` — the centerpiece recommendation query
   - `sql/04_similar_users.sql` and `sql/06_bonus_queries.sql` — optional
     deeper-dive queries

No `CREATE DATABASE` step is needed — Oracle uses your existing schema/user
as the container, unlike MySQL's separate database concept.

## Optional: scale up to ~20,000 ratings

`sql/07_bulk_sample_data.sql` replaces the small curated dataset with a
larger, randomly generated one — 500 users, 200 movies, and ~20,000 ratings.
Run it with **F5 (Run Script)** after `01_schema.sql` instead of
`02_sample_data.sql`. It uses a PL/SQL loop with `DBMS_RANDOM` and skips
duplicate (user, movie) pairs automatically, then prints how many rows
were inserted and a row-count summary.

Since the data is randomly generated (not curated like the small dataset),
recommendation results for any given `user_id` will vary and may be less
tightly clustered by taste — that's expected and fine for demonstrating
scale/performance, but if you want the deliberately-similar-taste demo
from before, stick with `02_sample_data.sql`.

## Option: real MovieLens data (~19,300 ratings)

`sql/08_movielens_real_data.sql` replaces the sample data with a real slice
of the **MovieLens 25M dataset** (grouplens.org/datasets/movielens/25m) —
a well-known, publicly available dataset used throughout recommendation-
system research and tutorials. It contains:

- **160 real users** (first 160 user IDs from the original dataset)
- **4,370 real movies** they actually rated, with real titles and release years
- **19 real genres** (Action, Adventure, Animation, Comedy, Drama, etc. — using
  each movie's primary/first-listed genre to fit this schema's one-genre-per-movie design)
- **19,318 real ratings**, converted from MovieLens's 0.5–5.0 half-star scale
  to this schema's 1–5 whole-star scale (rounded to nearest star)

Run it with **F5 (Run Script)** after `01_schema.sql`, instead of
`02_sample_data.sql` or `07_bulk_sample_data.sql`. It's a large file
(~2.2 MB, ~19,300 INSERT statements) so the script may take a minute
to finish — that's expected.

**Why this is worth using:** unlike synthetic/random data, this is real
public data with a citable source — "I used the MovieLens 25M dataset,
sampled to ~19K ratings" is a stronger, more credible line in an interview
than "I made up some sample data." MovieLens usernames/emails are
synthetic placeholders (the dataset doesn't include real names), but every
user ID, movie, rating, and timestamp is unmodified from the original data.

## Oracle-specific notes

- Tables use `NUMBER GENERATED BY DEFAULT AS IDENTITY` instead of
  `AUTO_INCREMENT` for auto-numbering primary keys.
- `FETCH FIRST n ROWS ONLY` is used instead of `LIMIT`.
- `VARCHAR2` is used instead of `VARCHAR` (Oracle convention).
- `02_sample_data.sql` sets `NLS_DATE_FORMAT` for the session so plain
  `'YYYY-MM-DD'` date strings insert correctly.

## Tech

Oracle Database (XE or higher) — uses window functions (`RANK()`,
`AVG() OVER (...)`), which Oracle has supported since 8i.

## Interview talking points

- The core recommendation query (`05_recommendations.sql`) is the centerpiece —
  be ready to explain it line by line.
- Know the `LEFT JOIN` alternative to the `NOT IN` subquery (included in the
  same file) — a common follow-up question.
- Be upfront that this is collaborative-filtering *logic*, not a trained
  ML model — the honesty lands better than overclaiming.
